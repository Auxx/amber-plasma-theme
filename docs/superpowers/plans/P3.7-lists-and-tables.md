# P3.7 Lists and Tables Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Union style draws the items of list, tree, table and icon views, sidebars, tree chevrons and headers in the prototype's tones and sizes, in every state, with the block marker on a selected item's leading edge and no line anywhere. This is checked by pixels in a Qt Widgets application and by eye in Dolphin and Kate.

**Architecture:** This plan rewrites, where they stand, the `itemviewitem`, the Qt Quick delegates and `focusframe` of `delegate.css`, every block of `tables.css`, the `listview`, `treeview`, `tableview` and `columnview` part of the view block in `application.css`, and whatever element Task 1 finds for a Qt Widgets header and branch. They use only the variables of the generated `tokens.css` (D-97). The check is P3.3's to P3.6's: `browser states` gives the gallery's expectation, the probe draws each state, and `image states --region` compares one part of a widget. An item is a strip of a larger view, so every comparison names the region that the probe writes into the manifest: the item, its leading 3 px, a cell, a chevron, a header section. Task 1 first finds out what Union reaches on views in Qt Widgets: P3.2 left Qt's grid of a table view, and P3.6 found that no view rule reached what lies behind a scrollbar. Task 2 adds to the prototype the states it does not show yet: a tree item and a table row as state rows, a focused and a disabled selected item, a disabled header section.

**Tech Stack:** Union CSS (`plasma-union` 6.8.2), Node 24 with `node:test`, the `browser`, `image`, `generate` and `tokens` tools, PySide6 6.11.2, the nested `kwin_wayland` session of P2.3 to P3.6 (`tmp/check-colour-scheme/`), Dolphin, Kate.

**Spec:** `docs/product/roadmap.md` (row P3.7 and the notes under Step 3: the accent frame of a current item, the lines between header sections, the grid of a table view, the settings dialog's page list), `docs/architecture/design-language.md` ("Surfaces"; "Widgets": the item and header section rows, and the bullets on precedence, selection, secondary text, views and scrollbars; the widget tokens), `prototype/widgets.css` (`.item`, `.header`, `.tree`, `.table`), `prototype/shell.css` (`.sidebar`, `.list`, `.row`), `prototype/gallery.html` (the rows `item` and `header`, and the live tree and table), `docs/architecture/platform.md` ("Union": focus in the Breeze style, what Union tells a button, the bars), `docs/architecture/decisions.md` (D-21, D-72, D-73, D-90, D-95, D-97, D-98, D-103, D-108, D-109), `docs/superpowers/plans/P3.6-bars.md` (the probe's regions, the border drawn at rest, and the outcome).

## Global Constraints

- Branch `feat/p3.7-lists-and-tables` from `master`. This plan file is committed on it.
- Use the glossary's words in British spelling: item, view, sidebar, header, header section, sort arrow, chevron (new, Task 2), rubber band (new, Task 2), block marker, selected, focused, hovered, pressed, disabled, at rest, surface, tone, known gap. In a table view an item is a whole row; a "cell" is one column of it. Never "column header" for the whole header, "branch indicator" or "expander" for a chevron, or "delegate" in prose, except in Union's own selectors (`itemviewitem`, `headerviewdelegate`, `selectionrectangle`) and Qt's names (`PE_IndicatorBranch`, `CE_RubberBand`).
- **Never change the owner's system settings.** `sha256sum ~/.config/kdeglobals ~/.config/kwinrc ~/.config/dolphinrc ~/.config/katerc` gives the same result at the start (Task 1) and at the end (Task 5). Nothing is written under `~/.config`, `~/.local/share` or `/usr`. Switching Dolphin's view mode, opening its settings dialog or Kate's, is done in the nested session, whose configuration lives in `tmp/check-colour-scheme/config/`.
- **Anti-goals.** No rounded corner, no hairline and no cool grey. Every `border-radius` of the view blocks is `0px`, the `[position]` rules included. No item is inset from its row: Breeze's `inset: 2px` leaves a strip of the view's tone round a hovered item, so every `inset` side of an item is `0px`. A table has no grid line, a tree no branch line, a header no line between its sections or under it. The only borders allowed are the selected item's block marker (below), the selected tab's (P3.6) and P3.4's focus bar.
- **The target tones** are the design language's, as the prototype draws them. Each cell gives background / text; "detail" is an item's secondary text, such as a size, and the chevron of a tree folder:

  | Widget | At rest | Hovered | Focused | Pressed | Selected | Disabled |
  |---|---|---|---|---|---|---|
  | Item (list, tree, icon, sidebar) | no fill / `text`, detail `text-dim` | `tone-3` / `text`, detail `text-dim` | `raised-focus` / `text`, detail `text` | as hovered (my call) | `selected` / `text`, detail `text-dim`, marker `accent` | no fill / `text-dim` |
  | Selected item | — | as selected (D-73) | `raised-focus` / `text`, detail `text`, marker | as selected | — | `selected` / `text-dim`, marker (my call) |
  | Table row | as an item; the marker on its first cell only | | | | | |
  | Header section | no fill / `text-dim` | `tone-3` / `text` | — | `tone-1` / `text` | sorted: no fill / `text`, sort arrow `text` | no fill / `text-dim` (my call) |
  | Header past its last section | no fill | — | — | — | — | — |
  | View | `tone-2`; a sidebar `tone-1` | — | no tint (my call) | — | — | — |

  Precedence: pressed beats focused, and focused beats hovered. A disabled widget never changes. Within a block, the state blocks come in the order hovered, focused, pressed, selected (`:highlighted` or `.selected`), disabled (P3.3: the later block wins), except that a selected item's `:hovered` changes nothing, and a selected disabled item keeps its tone and marker.
- **Sizes** (the prototype): an item of a list, tree or table is 26 px high, its text 12 px from its leading edge with the marker counted in those 12 px, and each cell of a table row is padded 12 px at the sides, as a header section is. A tree indents 20 px a level, and a leaf's text starts where a folder's name does. A header section is 26 px high, padded 12 px at the sides. The block marker is `var(--marker-width)` (3 px) wide along the item's whole leading edge. An icon view's tiles keep Breeze's size. If Union cannot reach a size, or an application sizes its own rows (Dolphin), record what it reaches and why in `platform.md` and keep the nearest size. This alone is not a reason to stop.
- **Decisions of this plan** (my call, recorded as D-110 in Task 5, and drawn in the prototype in Task 2 before the style):
  - **The marker sits on the leading edge**: the left, or the right in a right-to-left layout. It is drawn as a `border-<edge>` in `accent`, set at rest in `transparent` and, in each state that has a fill, in that fill, since Union draws only a border that exists at rest and draws no background under it (P3.6). In a table row only the first cell carries it (`[position="beginning"]` or `"invalid"`, as Task 1 finds).
  - **An item shows focus only under keyboard focus** (`:visual-focus`), as the prototype's `:focus-visible` does. A view that has focus always has a current item, and Dolphin's view nearly always has focus: under `:active-focus` one item would always be tinted. This is the reverse of a well (D-103), whose text cursor is focus itself.
  - **A focused view takes no tint** in Qt Widgets. The prototype's tinted scroller is a browser's; Dolphin's and Kate's views have focus nearly always. The focused item shows focus.
  - **A pressed item** is drawn as hovered: the design language gives an item no pressed tone, and a click selects it at once.
  - **A disabled selected item** keeps `selected` and its marker, with `text-dim`, as a disabled selected tab does (P3.6). `text-dim` on `selected` is 4.60:1.
  - **A disabled header section** is `text-dim` with no fill.
  - **A settings dialog's page list** is drawn as a sidebar: `tone-1`, the dialog's body, with items as above (the roadmap's note under Step 3).
  - The Qt Quick delegates (`itemdelegate`, `checkdelegate`, `radiodelegate`, `switchdelegate`, `swipedelegate`, `treeviewdelegate`, `tableviewdelegate`, `headerviewdelegate`) take the same rules as `itemviewitem` and the header. They are checked by the spec only, as the Qt Quick parts of P3.3 to P3.6 were.
  - The inactive window changes no item: Qt's inactive Selection colours are the colour scheme's, and the style reads none.
- **The rubber band** (the rectangle dragged over a view to select items) has no token: Breeze draws it as the highlight colour at 75 % opacity, and the design language does not name it. If Task 1 finds that a Union rule reaches it, Task 2 shows the owner two candidates in the gallery, `selected` at 50 % opacity as a new token `--rubber-band` and the same at 30 %, each with no border. The owner chooses before Task 3. If no rule reaches it, it is listed in Task 4 for the owner as what it is.
- **Contrast pairs.** Every pair this family uses must exist and pass: `text` on `tone-1`, `tone-2`, `tone-3`, `selected` and `raised-focus`; `text-dim` on `tone-1`, `tone-2`, `tone-3` and `selected`; `accent` on `selected` and `raised-focus` (the marker, 3:1). All are present now. `node tools/src/bin/tokens.mjs pairs` passes. A pair for `--rubber-band`, if the owner chooses one, is added beside it in `prototype/tokens.css`. No other new token is expected; if one is needed, it goes to the owner first.
- **Stop and ask the owner** before Task 3 if Task 1 finds that Union cannot tell a selected item from the others in a Qt Widgets view, or cannot draw a 3 px mark on its leading edge, or that Qt draws a table's grid, a tree's branch lines or a header's dividers and no rule removes them. A selected item with no marker changes what Amber is, and a line is an anti-goal (CLAUDE.md, "Stop and ask"). Offer what Task 1 found. Ask too if Union gives an item no state that tells keyboard focus from a click, since an item tinted after every click changes the look. Anything else Union cannot reach becomes a known gap and goes to the owner in Task 4: a page list's or a view's background that no rule reaches; rows that Dolphin sizes or paints itself; a marker that stays on the left in a right-to-left layout; secondary text that Qt or Dolphin draws from the colour scheme; the rubber band.
- **Edited rules stay where they were.** Change values in place. Delete a declaration that reads the colour scheme only where a token replaces it. Delete from `:root` the `--delegate-*` and `--focus-highlight-color` variables, and any `--view-*`, `--highlight-*` or `--button-*` variable, that no rule uses any more. Blocks outside this family keep their variables; the bars of P3.6 are not touched.
- Files of the nested session and the probe stay in `tmp/` and are not committed, as in P2.3 to P3.6.

## Review Focus

- **The marker on every cell of a table row.** Union gives each cell its own `itemviewitem`, so a rule on the item draws a 3 px accent bar at the start of each column. This is pinned in Task 4 by the case `table-view`: `image colours` over `marker` of the first cell lists only `#d1b072 accent`, and over `cell-2-lead` and `cell-3-lead`, the leading 3 px of the other cells, it lists no accent.
- **A focused item after a click.** If the rules use `:active-focus`, a clicked item in a focused view takes `raised-focus` and keeps it, so that Dolphin always shows one item tinted. This is pinned in Task 4 by the state `clicked` of `list-view` (a mouse press and release on an item), aliased to the gallery's `selected`: its fill is `selected`, not `raised-focus`.
- **A strip of view round a hovered or selected item.** Breeze insets an item by 2 px and rounds it. This is pinned in Task 4: `image frame --surface <view>` exits 0 on every item region, and `image colours` over the item region's outer 1 px lists only the state's fill (and `accent` on the leading edge of a selected item).
- **A line left by Qt.** A `QTableView` draws its grid by default and a `QTreeView` may draw branch lines, neither through an item rule. This is pinned in Task 4 by the cases `table-view` (`showGrid` left at its default, `True`) and `tree-view` (`rootIsDecorated` True, three levels): `image frame` exits 0 on both, `header-row` included.
- **The marker on the wrong edge in a right-to-left layout.** A `border-left` stays on the left when the layout turns. This is pinned in Task 4 by the case `list-view-rtl` (`setLayoutDirection(Qt.RightToLeft)`): `image colours` over its `marker` region, now the right 3 px, lists only `accent`, or the case goes to the owner as a known gap.
