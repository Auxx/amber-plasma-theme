# P0.2 Tools base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Amber its `tools/` folder with a working `colour` tool (convert, contrast, solve), tests, and the `ai-tools` skill that describes it.

**Architecture:** The `colour` tool is ported from the owner's `front-burner` project (`/home/aux/dev/front-burner/tools/ai-tools`, MIT, same owner). Logic lives in `tools/src/lib/`, the command line in `tools/src/bin/`. In this plan a value is a CSS colour only; token names arrive with the `tokens` tool in P1.1. Tests use Node's own test runner.

**Tech Stack:** Node 24 (ES modules, `.mjs`, no build step), `node:test`, `node:assert/strict`, `node:util` `parseArgs`, culori 4.0.2.

**Spec:** `docs/architecture/tooling.md`, `docs/architecture/accessibility.md` ("First measurements"), `docs/product/roadmap.md` (plan P0.2).

## Global Constraints

- Use the glossary's words (`docs/product/glossary.md`); British spelling: "colour".
- culori is the only dependency, pinned to exactly `4.0.2`. No other package.
- Tools never write outside the repository. Nothing under `/usr`; no system settings.
- Exit codes: 0 success; 1 a check failed or an error occurred; 2 the command line was wrong.
- Every command offers `--json`.
- Do not copy the `tokens`, `story`, `icons`, `doc-ids`, `nx-tags`, `typing-test`, `mem-profile`, `vitest-configs` or `workspace` files from front-burner.
- Ported files keep their logic unchanged. Change only: import paths, usage paths, and comments or messages that mention Storybook, the token page, `--ui-` tokens or colour schemes.
- Each ported file starts with the comment `// Ported from front-burner tools/ai-tools (MIT, same author).`

## Review Focus

- `--min` that is not a number (`--min abc`): exits 2 with the usage, not a silent FAIL.
- A value that is not a colour (`contrast banana '#000'`): exits 1 and names the value.
- A background whose bottom layer is not opaque: the result says so and is not reported as a plain pass.
- A part-transparent foreground (a glow): painted over the background before measuring, not measured as if opaque.
- Fewer than two values for `contrast`, or none for `convert`: exits 2 with the usage.

describe('Amber starting tokens', () => {
  const ratio = (fg, ...bg) =>
    Number(measureContrast(parseColour(fg), bg.map(parseColour)).ratio.toFixed(2));

  it('matches the first measurements', () => {
    assert.equal(ratio('#e8e3da', '#25221f'), 12.38); // text on tone 2
    assert.equal(ratio('#9c958a', '#312e29'), 4.56);  // dim text on tone 3
    assert.equal(ratio('#d1b072', '#25221f'), 7.66);  // accent on tone 2
    assert.equal(ratio('#fbf3e6', '#b5442f'), 4.97);  // on-danger on danger
    assert.equal(ratio('#151413', '#1c1a18'), 1.06);  // tone 0 on tone 1
  });

  it('fails text on danger and dim text on tone 4', () => {
    assert.ok(ratio('#e8e3da', '#b5442f') < 4.5);
    assert.ok(ratio('#9c958a', '#3c3832') < 4.5);
  });

  it('marks dim text on tone 3 as close to 4.5', () => {
    assert.equal(isClose(4.56, 4.5), true);
    assert.equal(isClose(4.97, 4.5), false);
  });

  it('paints a part-transparent glow over its surface before measuring', () => {
    const glow = { ...parseColour('#d1b072'), alpha: 0.45 };
    const { ratio: r, opaque } = measureContrast(glow, [ parseColour('#25221f') ]);
    assert.equal(opaque, true);
    assert.ok(r > 1 && r < 7.66);
  });
});
