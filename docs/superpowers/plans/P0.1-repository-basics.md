# P0.1 Repository basics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the Amber repository its ignore rules, its MIT licence and a README stub, and make the first commit.

**Architecture:** Three files at the repository root. Folders of the layout in the overview are not created empty: git does not track empty folders, so each folder appears with its first file, in the plan that fills it.

**Tech Stack:** git, plain text and Markdown.

**Spec:** `docs/product/roadmap.md` (plan P0.1), `docs/architecture/overview.md` (repository layout), `docs/architecture/decisions.md` (D-22, MIT licence).

## Global Constraints

- Use the glossary's words (`docs/product/glossary.md`): "Amber", "part", "prototype", "known gap".
- Write nothing under `/usr` and change no system settings.
- Licence: MIT (D-22).
- Do not change any file under `docs/` except the status of P0.1 in the roadmap and its "done when" wording (Task 1, Step 5).

## Review Focus

- `.superpowers/` holds brainstorming mockups and a session key in file names and state; it must never be committed.
- `.idea/` holds the owner's editor settings; it must not be committed.
- The README must not claim anything is installable yet: no part exists.
