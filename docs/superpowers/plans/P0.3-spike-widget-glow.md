# P0.3 Spike: widget glow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer three questions about Union on the owner's machine and write the answers into the platform document: can a coloured, blurred `box-shadow` show as a glow on a Qt Widgets button; can one application run with a style installed for the user; and where is such a style installed.

**Architecture:** A throwaway Union style, `amber-spike`, is a copy of the Breeze style plus one file of glow rules. It is installed for the user with `union-styletool install` and used by one small PySide6 test application through `UNION_STYLE_NAME`. The application lays buttons out in the places where a glow could be clipped and can save a picture of its own window. Nothing of the spike is kept except its findings.

**Tech Stack:** `plasma-union` 6.8.2 (`union-styletool`, `union-ruleinspector`), Union CSS, Python 3 with PySide6 6.11.2 (Fedora's package, built on the system's Qt 6.11.2, so it loads `UnionWidgetsStyle.so`).

**Spec:** `docs/architecture/platform.md` ("Union", its "Unverified" table and "Spike findings"), `docs/architecture/design-language.md` ("Glow and shadow"), `docs/product/roadmap.md` (row P0.3).

This is a spike, so the plan has no tests to write first. Each step is an action with something to observe, and what is observed is noted for Task 4. The spike's own files are not held to the anti-goals, because they are deleted; the glow rules still remove the button's border and radius so that a border is not mistaken for a glow that reads as a line.

## Global Constraints

- Use the glossary's words (`docs/product/glossary.md`); British spelling.
- Never change the owner's system settings. `widgetStyle` in `~/.config/kdeglobals` reads `Union` before and after; nothing under `~/.config` is edited. Union's own writes to `~/.cache/union` and the files `union-styletool install` creates are allowed.
- Write nothing under `/usr`.
- All spike files live in `tmp/spike-glow/` in the repository (`tmp/` is ignored by git). None is committed.
- The style's identifier is `amber-spike`, not `amber`, so that it can never be mistaken for the real style of P3.1.
- Glow values come from the design language: accent `#d1b072` = `rgb(209, 176, 114)`; hovered 14 px blur at 28 % alpha; focused 18 px blur at 45 % alpha; no offset, no spread.
- A fact goes into the platform document as "verified" with the date of the run only if it was seen on this machine in this spike.
- **Stop and ask the owner** if the glow cannot be drawn, or if the style cannot be used by one application alone. Write the reason into the platform document first (Task 4), then stop: what replaces the glow is the owner's decision (D-38).

## Review Focus

Ways this spike could give a wrong answer, most likely first. Each is pinned by a step.

- The test application is not drawn by Union at all (it fell back to another Qt style), so nothing seen says anything about Union. Pinned in Task 1, Step 3.
- A stale style cache shows the previous CSS, so a change seems to have no effect, or an old glow seems to work. Pinned in Task 2, Step 5 and Task 3, Step 1.
- The picture saved by the application differs from what the compositor shows on screen. Pinned in Task 3, Step 4: the owner looks at the live window.
- The glow shows on a button with room around it but is cut where a button touches a neighbour, a parent's edge or the window's edge. Pinned in Task 3, Step 2.
- `union-styletool install` changes a setting or writes somewhere unexpected. Pinned in Task 2, Steps 2 and 3.

- [x] **Step 1: Set the roadmap's P0.3 row to "in progress"**

Modify `docs/product/roadmap.md`, row P0.3, status `in progress`. It is not committed on its own: Task 4 sets the final status and commits the row.

- [x] **Step 2: Write `tmp/spike-glow/app.py`**

A PySide6 `QApplication` with one `QWidget` window, 520 × 420, window background left to the style. It does not call `setStyle` or `setStyleSheet`. Contents, top to bottom, the outer layout with contents margins 0 and spacing 24:

| Name | What | Tests |
|---|---|---|
| `edge` | A `QPushButton` in the window's top-left corner, with no margin to the window's edge | clipping by the window's edge |
| `touch-1`, `touch-2` | Two buttons in a row with spacing 0 | a neighbour painting over the glow |
| `near-1`, `near-2` | Two buttons in a row with spacing 4 | the same, at the Breeze style's spacing |
| `framed` | A button inside a `QFrame` whose layout has contents margins 0, the frame given a fixed height equal to the button's | clipping by the parent's edge |
| `beside-field` | A button with a `QLineEdit` directly to its right, spacing 0 | a different widget kind as neighbour |
| `free` | A button with at least 40 px of empty surface on every side | the control case |

Each button's `objectName` and text are its name. On start the application prints one line: `style: <QApplication.style().metaObject().className()> / <QApplication.style().objectName()>`.

Options:
- `--focus <name>`: after the window is shown, call `setFocus(Qt.FocusReason.TabFocusReason)` on that button, so that it is focused as by the keyboard.
- `--grab <png>`: 600 ms after the window is shown, save `window.grab()` to the path, print `saved <png> at scale <devicePixelRatio>`, and quit. Without it the window stays open.

- [x] **Step 3: Run the baseline and check that Union draws the application**

Run: `python3 tmp/spike-glow/app.py --grab tmp/spike-glow/shots/baseline.png`
Expected: the `style:` line names a Union class (it contains `Union`). Read the picture: Breeze-style buttons with rounded corners and a border.

If the class is not Union's, stop here: find out why (`QT_DEBUG_PLUGINS=1`, the platform theme) before going on. Do not pass `-style` or set `QT_STYLE_OVERRIDE` without noting it as a finding, because the applications Amber targets get Union from the system setting.

Note for Task 4: the class name, and the scale.

### Task 2: Install the spike style for the user and run one application with it

**Files:**
- Create: `tmp/spike-glow/amber-spike/metadata.json` (thrown away)
- Create: `tmp/spike-glow/amber-spike/contents/css/` — a copy of `/usr/share/union/styles/breeze/contents/css/` plus `spike.css` (thrown away)

**Interfaces:**
- Consumes: `app.py` and its options from Task 1.
- Produces: an installed style `amber-spike`; the command prefix `UNION_STYLE_NAME=amber-spike`; the noted install path.

- [x] **Step 1: Build the style folder**

Copy `/usr/share/union/styles/breeze/contents/css/` to `tmp/spike-glow/amber-spike/contents/css/`. Write `metadata.json` in the shape of Breeze's:

```json
{
    "input-type": "css",
    "input-version": 1,
    "name": "Amber spike",
    "description": "Throwaway style for plan P0.3.",
    "version": "0",
    "license": "BSD-2-Clause",
    "authors": [ "Amber" ]
}
```

Add `@import "spike.css";` as the last line of `style.css`. Write `spike.css` with the loud version first, so that "is anything drawn" has an answer no one can doubt:

```css
button {
    border: none;
    border-radius: 0px;
    box-shadow: 0px 0px 18px 0px rgba(209, 176, 114, 1.0);
}
```

If `border-radius: 0px` is refused, set `--corner-radius: 0px` in a `:root` block instead and note it.

- [x] **Step 2: Record the state before installing**

Run: `grep -n widgetStyle ~/.config/kdeglobals; union-styletool list; touch tmp/spike-glow/before-install`
Expected: `widgetStyle=Union`; the list shows only `breeze`.

- [x] **Step 3: Install, and find where it went**

Run: `union-styletool install tmp/spike-glow/amber-spike`
Then: `union-styletool list; union-styletool inspect amber-spike; find ~/.local ~/.config ~/.cache -newer tmp/spike-glow/before-install -not -path '*/claude/*' 2>/dev/null; grep -n widgetStyle ~/.config/kdeglobals`

Expected: the list shows `amber-spike`; `find` shows the installed folder. Note for Task 4: the full install path; whether the files are copies or links to `tmp/`; the identifier the tool gave the style and where it took it from (the folder's name or the metadata); anything written outside the style's folder.

If anything under `~/.config` changed, or `widgetStyle` is no longer `Union`: run `union-styletool uninstall amber-spike`, tell the owner exactly what changed, and stop.

If `install` fails or asks questions, read its message, try `union-styletool create --help` for the shape it expects, and note what was needed. Do not install by copying files by hand unless the tool cannot do it; if it comes to that, it is a finding.

- [x] **Step 4: Check that the rules of the installed style match a button**

Run: `union-ruleinspector --style amber-spike --type button`
Expected: the output includes the `box-shadow` of `spike.css`. This separates "the style was not loaded" from "the style was loaded but the shadow is not drawn" in the next step.

- [x] **Step 5: Run the application with the style**

Run: `UNION_STYLE_NAME=amber-spike python3 tmp/spike-glow/app.py --grab tmp/spike-glow/shots/loud.png`
Then, once: `UNION_STYLE_NAME=amber-spike UNION_FORCE_RECREATE_STYLE_CACHE=1 python3 tmp/spike-glow/app.py --grab tmp/spike-glow/shots/loud-fresh-cache.png`

Read both pictures and compare with `baseline.png`. Expected: square buttons without a border, each surrounded by a strong gold blur; the two pictures are alike. Run the baseline command again with no variable and confirm it still looks like Breeze: the style reaches one application alone.

Note for Task 4: whether `UNION_STYLE_NAME` worked; whether the first run already showed the new style or only the run that recreated the cache did; what appeared in `~/.cache/union`.

If the application still looks like Breeze, tell the cases apart before concluding:
1. `UNION_STYLE_NAME=breeze-mobile python3 tmp/spike-glow/app.py --grab …` — if this changes the look, the variable works and the user's style is not found; if not, the variable is not read by the widgets style.
2. `strace -f -e trace=openat -o tmp/spike-glow/trace.txt` on the run, then search the trace for `union/styles` to see which folders Union looks in.
3. `QT_LOGGING_RULES="*union*=true"` on the run, for Union's own messages.

If no way is found to give one application a user's style, that is the finding: go to Task 4, then stop and ask the owner.

### Task 3: The glow itself

> **Outcome, 2026-11-11:** the Qt Widgets style draws no shadow at all, so Steps 2 to 4 could not be done and stay unticked. A check not planned here was added: the same style in a Qt Quick window, where the glow is drawn. See the finding in `docs/architecture/platform.md`.

**Files:**
- Modify: the installed style's `spike.css` (through `tmp/spike-glow/amber-spike/` and `union-styletool update`, or as Task 2 found the install to work)

**Interfaces:**
- Consumes: the installed `amber-spike`, the edit-and-reload loop noted in Task 2, the button names of Task 1.

- [x] **Step 1: Confirm the edit loop**

Change the loud colour in `spike.css` to `rgba(181, 68, 47, 1.0)` (danger), bring the change to the installed style, and grab again. Expected: the blur is red. Note the shortest sequence that shows an edit: whether `union-styletool update` is needed, and whether `UNION_FORCE_RECREATE_STYLE_CACHE=1` is. P3.1 will use this loop. Set the colour back.

- [ ] **Step 2: Look for clipping with the loud glow**

Read `loud.png` button by button and note, for each of `edge`, `touch-1`/`touch-2`, `near-1`/`near-2`, `framed`, `beside-field` and `free`: is the blur whole on all four sides; is it cut at a straight line, and whose edge is that line; does a neighbour paint over it, or does it paint over the neighbour. Measure in the picture how far the blur reaches from the button's edge, in pixels at the noted scale.

If the blur is cut everywhere but on `free`, find the least room that leaves it whole: widen the spacing of the `near` pair in steps (8, 12, 16, 24) and grab each.

- [ ] **Step 3: Replace the loud rule with the design language's amounts**

```css
button {
    border: none;
    border-radius: 0px;
    box-shadow: none;
}

button:hovered {
    box-shadow: 0px 0px 14px 0px rgba(209, 176, 114, 0.28);
}

button:visual-focus {
    outline: none;
    box-shadow: 0px 0px 18px 0px rgba(209, 176, 114, 0.45);
}
```

Run: `UNION_STYLE_NAME=amber-spike python3 tmp/spike-glow/app.py --grab tmp/spike-glow/shots/rest.png`
Run: `UNION_STYLE_NAME=amber-spike python3 tmp/spike-glow/app.py --focus free --grab tmp/spike-glow/shots/focus-free.png`
Run: the same with `--focus touch-1` and `--focus edge`.

Expected: `rest.png` shows no glow on any button; the focused button alone glows, softly, with no line where the glow meets the button or fades out. Note whether Breeze's focus outline is gone, whether the focused rule won over the hovered one, and whether the blur at these amounts looks like the browser's for the same values (a glow, not a hard-edged band).

If `:visual-focus` does not match after `--focus`, check with `union-ruleinspector --style amber-spike --type button --state visual-focus`, and try focusing with a synthesised Tab key press instead; note which is needed.

- [ ] **Step 4: The owner looks at the live window**

Start `UNION_STYLE_NAME=amber-spike python3 tmp/spike-glow/app.py` without `--grab` and ask the owner to: move the pointer over `free`, `touch-1` and `edge`; press Tab through the buttons; and say whether each shows a glow, whether any glow is cut, and whether anything reads as a line. Show them `loud.png` and `focus-free.png` beside the live window and ask whether the pictures match what is on screen.

Hover is checked only here: a pointer cannot be put over a widget from a script under Wayland in a way that can be trusted.

Note for Task 4: the owner's answers, in their words where they judge the look.
