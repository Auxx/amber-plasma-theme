# P1.2 Window shell Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A prototype page, opened from disk, with a mock file-manager window in front of a second window, every surface told apart by tone alone, and candidates for the window outline, the window glow and the shadow shown side by side with their measured contrast (for O-4).

**Architecture:** The window outline, window glow and shadow become tokens with starting values, so the page and, later, the decoration read them from one place. The tokens reader learns two new value forms: a length in `px`, and a part-transparent token written `color-mix(in srgb, var(--name) N%, transparent)`, so the glow is derived from accent instead of copying it. The page is plain HTML and CSS with no script: `window.css` draws what the decoration will draw, `shell.css` draws the file manager inside it. Two specs read the real files: one fails on any anti-goal in the prototype's CSS and HTML, the other recomputes every contrast figure printed under a candidate, so a printed number cannot go stale.

**Tech Stack:** HTML and CSS opened as `file://` (D-35); Node 24 ES modules, `node:test`, `node:assert/strict`; the existing `tools/src/lib/tokens.mjs`, `colour.mjs`, `cli.mjs`. No new dependency.

**Spec:** `docs/product/roadmap.md` (P1.2 and the paragraph under the Step 1 table), `docs/architecture/design-language.md` (Surfaces, Shadow, Window decoration), `docs/architecture/accessibility.md` (rule 5), `docs/architecture/decisions.md` (D-25, D-26, D-35, D-36, O-4), `docs/architecture/platform.md` (P0.4, P0.6).

## Review Focus

- A token value in a form the reader does not know (`1em`, `calc(…)`, `color-mix` in another space or with another second colour, `0%` or `120%`): the reader throws and names the file and line. Pinned in Task 1.
- A length token where a colour is expected (a pair's foreground, `resolve outline-width`): a `missing` pair or exit 1 with a message naming the token, never a crash or `NaN`. Pinned in Tasks 1 and 2.
- A tone changed in a later plan (P1.3 to P1.7) that makes a candidate's printed ratio wrong: the candidates spec fails and names the figure. Pinned in Task 4.
- A hairline or rounded corner slipped in through `border`, `box-shadow`, `outline`, `<hr>` or a `style` attribute: the anti-goals spec fails and names the file and line. Pinned in Task 3.
- The page opened from disk in Firefox as well as Chrome, with no server: nothing to fetch, no module, no script. Pinned in Task 3 (no `<script>`), checked by eye in Task 5.

### Task 1: Lengths and part-transparent tokens in the reader

**Files:**
- Modify: `tools/src/lib/tokens.mjs` (`parseTokenValue`, `resolveToken`)
- Test: `tools/src/lib/tokens.spec.mjs`

**Interfaces:**
- Produces, from `tools/src/lib/tokens.mjs`:
  - `parseTokenValue(text)` returns one of `{ ref: string }`, `{ ref: string, alpha: number }`, `{ length: { value: number, unit: 'px' } }`, `{ colour: Colour }`.
    - `color-mix(in srgb, var(--name) N%, transparent)`, spaces optional around the commas and inside `var()`, N from above 0 to 100: `{ ref: 'name', alpha: N / 100 }`.
    - `<number>px`, the number 0 or more: `{ length: { value, unit: 'px' } }`.
    - Anything else goes to `parseColour`; when that fails, the error is `Not a colour or a length in px: <text>`.
  - `resolveToken(tokens, name)` multiplies the alphas met along the chain into the final colour's `alpha` (a missing `alpha` counts as 1) and does not change the stored colour. Reaching a length throws `Not a colour: <name> is a length (<value>px)`, where `<name>` is the token that holds the length.
  - `formatTokenValue(value): string`: `var(--x)`, `color-mix(in srgb, var(--x) 28%, transparent)`, `1px`, or the hex, followed by ` / 50%` when the colour's alpha is below 1.

- [ ] **Step 1: Change and add tests in `tools/src/lib/tokens.spec.mjs`**

Add to `SOURCE`: `--gap: 1px;` and `--haze: color-mix(in srgb, var(--text) 50%, transparent);`, so `reads the :root block` expects size 7.

- `parses token values`: replace the `1px` assertion. `parseTokenValue('1px')` deep-equals `{ length: { value: 1, unit: 'px' } }`; `parseTokenValue('color-mix(in srgb,var( --accent ) 28%,transparent)')` deep-equals `{ ref: 'accent', alpha: 0.28 }`; `parseTokenValue('1em')` throws `/Not a colour or a length in px: 1em/`.
- `refuses what it does not understand`: change `--gap: 1px;` to `--gap: 1em;` (still `/tokens.css:2:/`). Add, each throwing `/tokens.css:2:/`: `--a: calc(1px + 1px);`, `--a: color-mix(in oklch, var(--b) 28%, transparent);`, `--a: color-mix(in srgb, var(--b) 28%, white);`, `--a: color-mix(in srgb, var(--b) 0%, transparent);`, `--a: color-mix(in srgb, var(--b) 120%, transparent);`, `--a: -1px;`.

- `refuses a length as a colour` (new): `resolveToken(tokens, 'gap')` throws `/Not a colour: gap is a length \(1px\)/`; via `--spacing: var(--gap)` it names `gap`. `checkPairs(tokens, [pair('gap', ['tone-2'], 1.3)])[0].status` is `'missing'`.
- `formats token values` (new): the four forms above, and `formatTokenValue(parseTokenValue('rgb(0 0 0 / 50%)'))` is `'#000000 / 50%'`.
