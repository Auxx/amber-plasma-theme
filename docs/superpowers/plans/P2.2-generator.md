# P2.2 Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate `Amber.colors` from the tokens and the table of roles with a `generate` tool, so that running it twice gives the same file and the tests fail when the committed file falls behind the tokens.

**Architecture:** `tools/src/lib/colour-scheme.mjs` gains the parts that turn the table into a file: the one rule the table holds (the disabled `ContrastAmount`) and `formatColourScheme(roles, tokens)`, a pure function returning the file's text. A new library, `tools/src/lib/generate.mjs`, lists the parts that can be generated (only the colour scheme for now) with their output path, and writes a part only when its text has changed. A new tool, `tools/src/bin/generate.mjs`, has one command per part, prints the result and writes only with `--write` (tooling rule 5). The generated file is committed at `parts/colour-scheme/Amber.colors`, and a spec over the real files fails when it differs from what the generator makes now.

**Tech Stack:** Node 24 ES modules, `node:test`, the existing `tokens.mjs`, `colour.mjs`, `colour-scheme.mjs` and `cli.mjs`. No new dependency.

**Spec:** `docs/product/roadmap.md` (P2.2), `docs/architecture/colour-scheme.md` (the table, the rules, the check), `docs/architecture/tooling.md` (planned `generate` tool, rules for every tool), `docs/architecture/overview.md` (tokens are the single source; parts are generated), `parts/colour-scheme/roles.json`, `docs/architecture/decisions.md` (D-89 to D-91).

## Global Constraints

- Branch `feat/p2.2-generator` from `master`; this plan file is committed on it.
- Use the glossary's words, British spelling: colour scheme, colour set, role, token, part. The tool's command is `colour-scheme`, named after the part.
- **Every colour in `Amber.colors` comes from a token** (D-89). The generator never writes a colour that is not a token's, so the anti-goal "no cool grey" holds for the file as it holds for the tokens. A spec checks it (Task 3).
- **Fail loudly** (tooling rule 7): the generator refuses a table with a missing role, an unknown token, a token with alpha below 1, or a `rule` it has no code for. It never writes a partial file.
- **Deterministic:** no date, time, version or path of the machine in the file. Groups and keys are sorted in code-unit order (`Array.prototype.sort()` with no comparer), which is KConfig's order in `BreezeDark.colors`: `ColorEffects:*`, `Colors:*` (with `Colors:Header][Inactive` after `Colors:Header`), `General`, `KDE`, `WM`; inside `General`, `ColorScheme`, `Name`, `shadeSortColumn`.
- **File format** (as `/usr/share/color-schemes/BreezeDark.colors`, read on 2026-11-12): a group line `[<group>]`, so `Colors:Header][Inactive` is written `[Colors:Header][Inactive]`; one `Key=value` per line with no spaces; a colour as `r,g,b` in decimal 0–255 (from `srgb8`); a boolean as `true`/`false`; a number as JavaScript's `String(n)` (`0`, `0.34`, `1`); a string as written. One blank line between groups; the file ends with one newline.
- **Header** (my call), four comment lines and a blank line before the first group:

  ```text
  # SPDX-FileCopyrightText: 2026 Aleksandr 'Aux' Ivanov
  # SPDX-License-Identifier: MIT
  # Generated from prototype/tokens.css and parts/colour-scheme/roles.json.
  # Do not edit: run node tools/src/bin/generate.mjs colour-scheme --write
  ```

- **The disabled `ContrastAmount`** (the table's one `rule`): the amount `a`, rounded to two places, at which `text` faded towards `tone-2` has the relative luminance of `text-dim`. Fading is a mix of the sRGB channels, `c = fg + (bg − fg) × a`, as `KColorUtils::mix` does in kguiaddons (unverified on this machine; P2.3 checks the effect by eye). Solve by bisection on unrounded channels over `[0, 1]` for at least 40 rounds. With today's tokens (`text` #e8e3da, `tone-2` #25221f, `text-dim` #a9a297) it is **0.34**, measured on 2026-11-12.
- **Committing the generated part** is my call (D-92, Task 4): the install script of P6.1 then needs no Node, and a change of a token shows in review as a change of `Amber.colors`.
- Paths stay inside the repository (tooling rule 6). The tool writes only `parts/colour-scheme/Amber.colors`. Installing it to `~/.local/share/color-schemes/` is P6.1's job, and selecting it is the owner's (D-24).
- No rounded corner, hairline or cool grey: this plan draws nothing; the file's colours are the tokens'.

## Review Focus

1. **A stale committed file.** Someone changes a token and forgets to regenerate. Expected: `npm --prefix tools test` fails and names the command to run. Pinned by `Amber.colors is up to date` (Task 3).
2. **A token with alpha** (such as `glow`) put into the table by mistake. Expected: the generator refuses with `group.key: <token> is not opaque` rather than dropping the alpha. Pinned in Task 1.
3. **A `rule` the generator does not know**, added to the table later. Expected: an error naming the role, not the rule's prose in the file. Pinned in Task 1.
4. **A string value with a newline or `[`** would break the INI file. Expected: refused with the role named. Pinned in Task 1.
5. **`--write` when nothing changed** rewrites the file and touches its time, which makes a second run look like a change. Expected: the second run reports `unchanged` and leaves the file alone. Pinned in Task 2.

### Task 2: The `generate` tool

**Files:**
- Create: `tools/src/lib/generate.mjs`, `tools/src/lib/generate.spec.mjs`
- Create: `tools/src/bin/generate.mjs`, `tools/src/bin/generate.spec.mjs`
- Modify: `.claude/skills/ai-tools/references/tools.md`, `.claude/skills/ai-tools/SKILL.md`

**Interfaces:**
- Consumes: `formatColourScheme`, `loadRoles` (`colour-scheme.mjs`); `loadTokens` (`tokens.mjs`); `main`, `print` (`cli.mjs`).
- Produces:
  - `PARTS` — `{ 'colour-scheme': { file, generate } }`, where `file` is the absolute path of `parts/colour-scheme/Amber.colors` and `generate()` returns its text from the real tokens and table.
  - `writePart(file, text) -> { changed: boolean }` — writes only when the file is absent or its content differs.
  - `generate colour-scheme [--write] [--json]`:
    - without `--write`: prints the file's text to stdout, exactly, and exits 0;
    - with `--write`: prints `parts/colour-scheme/Amber.colors: written` or `… unchanged`, exits 0;
    - `--json`: `{ "part": "colour-scheme", "file": "parts/colour-scheme/Amber.colors", "changed": <bool>, "written": <bool>, "content": <text> }`; without `--write`, `changed` says whether the file on disk differs and `written` is `false`;
    - a refused table: the error's message on stderr, exit 1.

- [x] **Step 1: Write the failing specs.**
  - `generate.spec.mjs` (lib), in a folder from `mkdtempSync(join(tmpdir(), 'amber-generate-'))`: `writes a new file` (`changed: true`, content equal); `leaves an equal file alone` (second call `changed: false`, and the file's `mtimeMs` is unchanged); `rewrites a different file` (`changed: true`).
  - `generate.spec.mjs` (bin), run as a program from the repository root as `tokens.spec.mjs` does: `prints the colour scheme` (status 0, stdout starts with `# SPDX-FileCopyrightText` and contains `[Colors:View]`); `prints the same text twice` (two runs, stdouts equal); `reports in JSON` (`part`, `file` as above, `written: false`); `rejects an unknown part` (status 2).
