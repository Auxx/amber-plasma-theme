# P5.1 Frame and Title Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate the window decoration's frame, a square tone 0 title bar with the window outline on every edge, as an Aurorae theme from the tokens. Show it in the nested KWin and match it to the prototype for active and inactive windows.

**Architecture:** The decoration is an Aurorae theme folder, `parts/decoration/amber/` (D-34). Its `metadata.desktop` is written by hand. Its `decoration.svg` and `amberrc` are generated from the tokens by a new library, `tools/src/lib/decoration.mjs`. The `generate` tool learns parts made of several files, and `generate decoration` prints or writes both. A spec fails when either file is stale (D-92). The frame is the nine plain rectangles of spike P0.4, once for each window state: edges and corners one `outline-width` thick in `outline`, the centre in `tone-0`. The title bar's height becomes a token. A new `image profile` command reads one row or column of a picture as runs of colour, named as tokens. With it, each edge of a window in the nested KWin is compared with the same edge of the prototype. This plan draws no window button (P5.2), no window glow or shadow, and nothing for maximised or tiled windows (P5.3).

**Tech Stack:** Node 24 ES modules with `node:test`; the `tokens`, `colour`, `generate`, `browser` and `image` tools; KWin and Aurorae 6.8.2 (`kwin-6.8.2-3.fc45`, `aurorae-6.8.2-1.fc45`) in the nested `kwin_wayland` session (`tmp/check-colour-scheme/`, with `run.sh`, `in.sh` and `shot`), whose `XDG_CONFIG_HOME` is `tmp/check-colour-scheme/config`. No new dependency.

**Spec:** `docs/product/roadmap.md` (row P5.1), `docs/architecture/design-language.md` ("Window decoration"), `prototype/tokens.css` (the decoration's tokens), `prototype/window.css` and `prototype/index.html` (the window shell), `docs/architecture/platform.md` ("Window decoration", its "Unverified" table, and the findings of P0.4 and P0.6), `docs/architecture/decisions.md` (D-3, D-13, D-25, D-34, D-44, D-62, D-63, D-92), `docs/architecture/overview.md` (the parts table: an Aurorae theme folder in `~/.local/share/aurorae/themes/`), `docs/architecture/tooling.md`.

## Global Constraints

- Branch `feat/p5.1-frame-and-title-bar` from `master`; this plan file is committed on it in Task 1.
- Glossary words: **window decoration** ("decoration" for short), **title bar**, **window outline** (never "border" or plain "outline"; KWin's "border size" is named only as KWin's setting), **tone**, **active** and **inactive** for windows, **token**, **part**. No new term is needed.
- **The theme's id is `amber`** (overview: parts with an identifier of their own use `amber`). Its folder is `parts/decoration/amber/` and holds `metadata.desktop`, `decoration.svg` and `amberrc`. KWin selects it with `theme=__aurorae__svg__amber`.
- **One new token, `--title-bar-height: 30px`** (D-44 allows a length), after `--outline-width` in `tokens.css`. It is the 30 px that `window.css` sets by hand, marked "my call, settled with the decoration in P5.1". `window.css`'s `.title-bar` uses `var(--title-bar-height)`. The window buttons keep their 30 px until P5.2.
- **The frame (`decoration.svg`).** Element ids are those of P0.4: `decoration-<side>` and `decoration-inactive-<side>`, where `<side>` is `topleft`, `top`, `topright`, `left`, `center`, `right`, `bottomleft`, `bottom` and `bottomright`. Each element is one `<rect>` with an opaque fill, `#rrggbb` from `srgb8`, with no stroke. The active and inactive frames are the same in this plan. They differ only in title text, which the `rc` file sets. Layout (my call): each frame is a 3 × 3 grid. Corners are `w × w` and edges are `w` thick, where `w` is `outline-width` in px. The centre is 30 × 30. The inactive frame sits below the active one with a gap of 8 px. Lengths are whole px; a token that is not one is refused. The file starts with an XML comment naming the generator, as the other generated parts do.
- **The `rc` file (`amberrc`)**, keys sorted within each group. The format comes from <https://develop.kde.org/docs/plasma/aurorae/>, and the rest is unverified until Task 3:
  - `[General]`: `ActiveTextColor` (`text`), `InactiveTextColor` (`text-dim`), `TitleAlignment=Center`, `TitleVerticalAlignment=Center`, `Animation=0`, `Shadow=true`. The colours are written `r,g,b,255`. `Shadow=true` is what spike P0.6 ran with; P5.3 tests `false`.
  - `[Layout]`: `BorderLeft`, `BorderRight` and `BorderBottom` take `outline-width`. `TitleEdgeTop` takes `outline-width`, so that the window outline lies above the title bar, not in its first row as in P0.4. `TitleHeight` takes `title-bar-height`. `TitleEdgeBottom=0`, `TitleEdgeLeft` and `TitleEdgeRight` take `outline-width`, and `TitleBorderLeft=0`, `TitleBorderRight=0`. `ButtonWidth` and `ButtonHeight` take `title-bar-height`, and `ButtonSpacing=0`. `PaddingTop`, `PaddingBottom`, `PaddingLeft` and `PaddingRight` are `0`: P5.3 gives the glow its room.
- **No window button file** is written in this plan. Without one, KWin shows no button (platform, verified 2026-11-11). Task 3 empties `ButtonsOnLeft` in the nested `kwinrc`, so the title bar holds the title alone. P5.2 draws the buttons and decides the menu button.
- **What "matches the prototype" means here** (my call). These are checked with `image profile` across each edge of a window, in both states:
  1. outside the window, then `outline` for `outline-width` device px on every edge, then the window;
  2. at the top, below the window outline, `tone-0` for `title-bar-height` device px, then the client, with no pixel of any other colour between;
  3. title text in `text` when active and `text-dim` when inactive (anti-aliasing blends between it and `tone-0` are ignored), centred on the title bar within 2 px;
  4. square corners: the window's corner pixel is `outline`.

  At scale 1.49, lengths are the logical length × 1.49, rounded either way. The prototype is shot at scale 1. Its glow and shadow sit outside the window outline, so the pixels outside are not compared.
- **Never change the owner's system settings.** At the start and end of Task 3, `sha256sum ~/.config/kwinrc ~/.config/kdeglobals` gives the same result, and `~/.local/share/aurorae/themes/` is still empty. KWin runs only in the nested session. That session finds the theme through a link, `tmp/check-colour-scheme/data/aurorae/themes/amber` → `../../../../../parts/decoration/amber`, which `run.sh` puts first in `XDG_DATA_DIRS`. That KWin finds Aurorae themes there is unverified and tested first. The nested `kwinrc` (`tmp/check-colour-scheme/config/kwinrc`) gets `[org.kde.kdecoration2]` with `library=org.kde.kwin.aurorae`, `theme=__aurorae__svg__amber`, `BorderSize=Tiny`, `BorderSizeAuto=false` and `ButtonsOnLeft=`. Installing the theme is P6.1's job.
- Paths stay inside the repository. `generate decoration --write` writes only `parts/decoration/amber/decoration.svg` and `parts/decoration/amber/amberrc`. Shots and probes stay in `tmp/` and are not committed.
- Anti-goals: no rounded corner, no line but the window outline, no cool grey. Task 3 runs `image lines` and `image greys` over every shot, leaving out the window outline's own rows and columns.
- **Stop and ask the owner** if any of these happens:
  - KWin does not find the theme through `XDG_DATA_DIRS`;
  - the window outline cannot be made the same width on every edge at scale 1.49;
  - a line other than the window outline shows between the title bar and the client;
  - the title font KWin draws differs from the prototype's `10pt "Noto Sans"`, regular.

- Consumes: `readPng` (`png.mjs`), `tokenNames` (`image.mjs`), `loadTokens` (`tokens.mjs`), `main`, `UsageError` (`cli.mjs`).
- Produces:
  - `profile(image, from: {x, y}, to: {x, y}, names?: Map<hex, string[]>) -> Array<{ colour: '#rrggbb', tokens: string[], length: number, at: {x, y} }>`: the pixels from `from` to `to` inclusive, in that order, as runs of one colour. `from` and `to` share a row or a column, and either may come first. Alpha is ignored. Throws when they share neither, or when a point lies outside the picture.
  - `image profile <png> --from x,y --to x,y [--json]`: one line per run, `#585248  outline  1 px  at 120,80`. A colour with no token shows `-`. Exit 0. A bad point is a usage error, exit 2.
