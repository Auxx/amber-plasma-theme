# P0.7 Browser tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `browser` tool that opens a prototype page in the installed Google Chrome. It saves screenshots of a page or of one element in a given state (hovered, focused or pressed), checks the rendered page for the anti-goals and for load errors, and prints the computed colours of elements named as tokens.

**Architecture:** `playwright-core` drives the system Chrome (`channel: 'chrome'`), so no browser is downloaded. Logic that needs no browser (paths, colour names) lives in `tools/src/lib/browser.mjs` and is tested without one. The parts that need Chrome are tested against `prototype/index.html` and a small fixture page, and those tests are skipped, with a reason, when Chrome cannot be launched. The command line in `tools/src/bin/browser.mjs` follows `cli.mjs` like `colour` and `tokens`.

**Tech Stack:** Node 24 ES modules, `node:test`, `playwright-core` 1.49.1 (pinned exactly), Google Chrome 157 at `/usr/bin/google-chrome`, the existing `cli.mjs` and `tokens.mjs`.

**Spec:** the owner's request on 2026-11-11 to use Playwright from `tools/` instead of the Chrome extension; `docs/architecture/tooling.md` (rules for every tool, the screenshot-tool paragraph); `docs/architecture/decisions.md` (D-42); the anti-goals in `docs/architecture/design-language.md`.

## Global Constraints

- Branch `feat/p0.7-browser-tool`. The plan is P0.7 in Step 0 because a tool is a foundation and nothing after it has to be renumbered. (my call)
- Tool rules 1–10 of `tooling.md` apply. Exit codes: 0 success; 1 a check failed or an error occurred; 2 the command line was wrong. Every command takes `--json`.
- Dependency: `"playwright-core": "1.49.1"`, exact, in `tools/package.json`. Do not add `playwright` or `@playwright/test`, and do not run `playwright install`. Verified on 2026-11-11 in a scratch folder: 1.49.1 drives Chrome 157 here.
- **Where files are written (rule 6).** Screenshots go to `tmp/` at the repository root by default; it is already in `.gitignore`. `--out` may name another path inside the repository or inside the system's temporary folder (such as `/tmp`), after following links; any other path is a usage error. (Narrowed in the final review: the first wording let `/usr` through.)
- The default viewport is 1300 × 900 at device scale 1. (my call)
- A page is given as a path relative to the repository root or an absolute path, and is opened as `file://`. There is no server (D-35).
- **Facts verified on 2026-11-11 with this version and this Chrome, which the plan builds on:**
  - A missing stylesheet on a `file://` page gives a `requestfailed` event with `net::ERR_FILE_NOT_FOUND`, plus a console error "Failed to load resource". The tool reports the request and drops that duplicate console line.
  - `locator.focus()` makes `:focus-visible` match.
  - `hover()` followed by `mouse.down()` makes `:active` match.

## Review Focus

- **Chrome missing or failing to start.** The tool exits 1 and says so: "Google Chrome could not be started (playwright-core uses the installed Chrome)". The Chrome tests are skipped with that reason; nothing hangs. Pinned in Task 2.
- **A state selector that matches no element, or more than one.** Exit 1, naming the selector and the count. Do not silently hover the first match. Pinned in Task 2.
- **`--out` under the home folder but outside the repository, a relative path that leaves the repository, or a name that does not end in `.png`.** Usage error (exit 2) before Chrome starts. Pinned in Task 1.
- **A colour that is part-transparent or not a token.** `colours` prints it plainly and does not force a token name onto it. `rgba(0, 0, 0, 0)` prints as `transparent`. Pinned in Task 1.
- **A page that loads with errors**, such as a broken link or a script error. `check` reports each one and exits 1, even when no anti-goal is broken. Pinned in Task 2.

### Task 1: Paths and colour names, without a browser

**Files:**
- Modify: `tools/package.json`, `tools/package-lock.json` (add `playwright-core` 1.49.1)
- Create: `tools/src/lib/browser.mjs`
- Test: `tools/src/lib/browser.spec.mjs`

**Interfaces:**
- Produces, from `tools/src/lib/browser.mjs`:
  - `REPO_ROOT`: the absolute repository root, from `import.meta.url`.
  - `pageUrl(path: string, root = REPO_ROOT): string`. Resolves a relative path against `root`. Returns its `file://` URL. Throws `No such page: <path>` when the file does not exist.
  - `outPath(path: string | undefined, { name: string, root = REPO_ROOT, home = os.homedir() }): string`. With no `path`, returns `<root>/tmp/<name>.png`. Otherwise resolves `path` against `root` and returns the absolute path. It throws a `UsageError` (from `cli.mjs`) in three cases:
    - `Not a .png file: <path>`
    - `Will not write under the home folder outside the repository: <path>`
    - a relative path that resolves outside `root`: also the home-folder message when `root` is under `home`.
  - `parseCssColour(text: string): { r, g, b, alpha }`, reading the `rgb(…)` and `rgba(…)` strings that `getComputedStyle` returns (0–255 and 0–1). Throws `Not a computed colour: <text>` on anything else.
  - `tokenNames(tokens: Map): Map<string, string[]>`. Maps the hex of every opaque colour token to its names, in tokens-file order. It uses `resolveToken`, skips lengths and part-transparent tokens, and includes tokens that are references, so `#3c3832` names both `tone-4` and `outline`.
  - `nameColour(text: string, names: Map): string`. Opaque gives `#1c1a18 (tone-1)`, or the bare hex when no token matches. Alpha 0 gives `transparent`. Any other alpha gives `rgb(r g b / NN%)`.

### Task 2: Opening a page in Chrome, and the `browser` tool

**Files:**
- Modify: `tools/src/lib/browser.mjs` (add the functions below)
- Create: `tools/src/bin/browser.mjs`
- Create: `tools/src/bin/fixtures/broken-page.html`
- Test: `tools/src/bin/browser.spec.mjs`

**Interfaces:**
- Consumes: Task 1's functions; `loadTokens` from `tokens.mjs`; `main`, `print`, `table`, `UsageError` from `cli.mjs`.
- Produces, from `tools/src/lib/browser.mjs`:
  - `openPage(url: string, { width = 1300, height = 900 } = {}): Promise<{ browser, page, problems: string[] }>`.
    - Launches `chromium` from `playwright-core` with `channel: 'chrome'` and `headless: true`, and opens `url` at device scale 1.
    - Collects `problems` while loading: `requestfailed` as `failed to load <path relative to root> (<errorText>)`; console errors other than "Failed to load resource" as `console: <text>`; and `pageerror` as `script error: <message>`.
    - A failed launch throws `Google Chrome could not be started (playwright-core uses the installed Chrome): <first line of the cause>`.
    - The caller closes `browser`.
  - `applyState(page, { hover, focus, press }: { [state]: string | undefined }): Promise<void>`. Each value is a CSS selector that must match exactly one element; otherwise it throws `<selector> matches <n> elements`. The states:
    - focus: `locator.focus()`;
    - hover: `locator.hover()`;
    - press: hover, then `page.mouse.down()`, with no release before the caller is done.
  - `renderedOffences(page): Promise<string[]>`. Runs in the page over every element and its `::before` and `::after` (when `content` is not `none`). It reports `<tag>.<classes>[::pseudo]: <property> <value>` for:
    - a border side with a width other than `0px` and a style other than `none`, as `border-<side> <width> <style>`;
    - a `border-radius` other than `0px`;
    - a `box-shadow` other than `none`;
    - a `text-decoration-line` other than `none`;
    - an `outline-style` other than `none` on any element that does not have the class `window`.
- Produces these commands:
  - `shot <page> [--selector css] [--hover css] [--focus css] [--press css] [--out file.png] [--full] [--width n] [--height n] [--json]`
    - Saves a PNG of the element (`--selector`, which must match exactly one element) or of the viewport, or of the whole page with `--full`, after applying the states.
    - Prints `Saved <path relative to the repository, or absolute> (<w> × <h>)`. JSON is `{ path, width, height }`.
    - The default name is the page's file name without `.html`, then the selector's letters and digits joined by `-`, then the states, such as `index-scene-front-hover`. (my call)
  - `check <page> [--width n] [--height n] [--json]`
    - Prints each load problem, then each rendered offence, then `<p> load problems, <o> anti-goal offences.`; JSON is `{ problems, offences }`.
    - Exits 1 when either list is not empty.
  - `colours <page> <selector> [--hover css] [--focus css] [--press css] [--json]`
    - One row per element matched: `element | background | colour`, named with `nameColour`.
    - JSON is a list of `{ element, background, colour }`.
    - Exits 1 when the selector matches nothing.
  - `--width`, `--height`: whole numbers from 200 to 4000; anything else is a `UsageError`.
