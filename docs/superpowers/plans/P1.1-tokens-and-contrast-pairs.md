# P1.1 Tokens and contrast pairs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Create Amber's tokens file and its contrast pairs, and a `tokens` tool whose `pairs` command runs in the tests with every pair passing.

**Architecture:** The tokens are CSS custom properties in `prototype/tokens.css`. The contrast pairs are in `prototype/contrast-pairs.json`, next to it. The `tokens` tool is ported from front-burner's (`/home/aux/dev/front-burner/tools/ai-tools/src/{lib,bin}/tokens.mjs`, MIT, same owner), with a new reader for one `:root` block and one scheme. A spec reads the real files, so a token change that breaks a pair fails `npm --prefix tools test`. Dim text fails on tone 4 (3.92:1), and this plan settles that by making it lighter.

**Tech Stack:** Node 24 ES modules (`.mjs`, no build step), `node:test`, `node:assert/strict`, the existing `tools/src/lib/cli.mjs` and `tools/src/lib/colour.mjs`. No new dependency.

**Spec:** `docs/product/roadmap.md` (P1.1), `docs/architecture/accessibility.md` (Amber's rules, How the check works), `docs/architecture/tooling.md` (planned tools, rules for every tool), `docs/architecture/design-language.md` (starting tokens).

## Global Constraints

- Use the glossary's words; British spelling ("colour").
- Tool rules 1–10 of `docs/architecture/tooling.md` apply. In particular: the parser fails loudly on input it does not understand, and the tokens file is never copied into code.
- Exit codes: 0 success; 1 a check failed or an error occurred; 2 the command line was wrong. Every command takes `--json`.
- Ported files start with `// Ported from front-burner tools/ai-tools (MIT, same author).` and drop everything about schemes, SCSS, Storybook, `workspace.mjs` and the `unknown` command.
- Token names (my call): `tone-0` … `tone-4`, `text`, `text-dim`, `accent`, `on-accent`, `danger`, `on-danger`. They are written `--tone-0` and so on in CSS, with no prefix. The tools accept a name with or without the leading `--`.
- Token values, from the design language, with one change: `text-dim` is `#a9a297` (was `#9c958a`). That is the same OKLCH hue (79.3) and chroma (0.018) at 71.6 % lightness instead of 67.3 %. It measures 4.60:1 on tone 4, which passes and is not close. (my call; the owner may change it in P1.7)
- Pair minimums: text and dim text 4.5; on-accent and on-danger 4.5; accent 3 (accessibility rules 1–2).
- No rounded corner, hairline or cool grey: this plan adds no visible element. The one colour it changes, `text-dim`, keeps its warm hue.

## Review Focus

- A declaration the parser does not know, such as `--outline: 1px;`, `color-mix(…)` or a rule outside `:root`: the parser throws and names the file and line. It does not skip the line.
- A pair that names a token that does not exist, such as a typo: the pair is reported `missing`, counts as failing, and `pairs` exits 1.
- `var()` references that form a cycle: an error that names the cycle, not a hang.
- A part-transparent token used as the bottom background layer: the pair is `missing` with a "not opaque" message, not a meaningless pass.
- A new token that carries text, added without pairs: the real-files spec fails and names the token.

### Task 1: Tokens and pairs library

**Files:**
- Create: `tools/src/lib/tokens.mjs` (port of front-burner `src/lib/tokens.mjs`, with a new reader)
- Test: `tools/src/lib/tokens.spec.mjs`

**Interfaces:**
- Consumes: `parseColour`, `measureContrast`, `isClose` from `tools/src/lib/colour.mjs`.
- Produces, from `tools/src/lib/tokens.mjs`:
  - `TOKENS_FILE`, `PAIRS_FILE`: absolute paths of `prototype/tokens.css` and `prototype/contrast-pairs.json`, resolved from `import.meta.url`.
  - `parseTokenValue(text: string): { ref: string } | { colour: Colour }`. `var(--name)` with optional spaces becomes `{ ref: 'name' }`. Anything else goes through `parseColour`, which throws `Not a colour: <text>`.
  - `parseTokens(source: string, file = 'tokens.css'): Map<string, Value>`. Strips `/* … */` comments. Requires exactly one `:root { … }` block and nothing else outside it but whitespace. Inside the block, each declaration is `--name: value;`. Throws `<file>:<line>: …` on any other line, on a value `parseTokenValue` rejects, and on a duplicate name.
  - `parseOverrides(list: string[] = []): { name, value }[]`, from `name=value` or `--name=value`. Throws `Not an override (token=value): <text>`.
  - `loadTokens({ overrides = [], file = TOKENS_FILE } = {}): Map<string, Value>`. An override replaces a token or adds a new one.
  - `resolveToken(tokens, name): { colour: Colour, chain: string[] }`. Throws `Unknown token: <name>`, with ` (via a → b)` when the name was reached through references, and `Token cycle: a → b → a`.
  - `parsePairs(source: string, file = 'contrast-pairs.json'): Pair[]`. Pair is `{ foreground: string, background: string[], minimum: number, why: string }`. Each JSON entry `{ foreground, on, minimum, why }` becomes one Pair per item of `on`. An item of `on` is a token name or an array of names, which are background layers from the bottom up. Throws `<file>: entry <n>: …` when `foreground` or `why` is not a non-empty string, `on` is not a non-empty array of names, or `minimum` is not a number from 1 to 21.
  - `loadPairs(file = PAIRS_FILE): Pair[]`
  - `checkPairs(tokens, pairs): Result[]`. Result is `{ pair, ratio?, status: 'pass' | 'fail' | 'missing', close?, error? }`. Any thrown error, and a background that is not opaque, gives `missing` with `error`.
  - `describePair(pair): string`, for example `text-dim on tone-2 + tone-3`.

- `reads the :root block`: `parseTokens(SOURCE)` has size 5, and `.get('label')` deep-equals `{ ref: 'text' }`.
- `refuses what it does not understand`: each of these throws, and the message matches the given pattern:
  - `':root {\n  --gap: 1px;\n}'` matches `/tokens.css:2:/`
  - `':root {\n  color: red;\n}'` matches `/tokens.css:2:/`
  - `':root { --a: #000; }\n.x { --b: #fff; }'` matches `/outside :root/`
  - `'--a: #000;'` matches `/no :root/`
  - `':root {\n  --a: #000;\n  --a: #111;\n}'` matches `/tokens.css:3:.*duplicate/i`
- `resolves references`: `resolveToken(parseTokens(SOURCE), '--label')` has `chain` deep-equal to `['label', 'text']` and colour `r` close to `232/255`.
- `names unknown tokens and cycles`: with `label` overridden to `var(--nope)`, resolving `label` throws `/Unknown token: nope \(via label → nope\)/`. Use `new Map([...parseTokens(SOURCE), ['label', { ref: 'nope' }]])`. With `a → b → a`, it throws `/Token cycle: a → b → a/`.
- `parses overrides`: `parseOverrides(['text-dim=#a9a297', '--accent=var(--text)'])` gives names `['text-dim', 'accent']`, and the second value deep-equals `{ ref: 'text' }`. `parseOverrides(['nope'])` throws `/Not an override/`.
- `expands pairs`: parsing `[{"foreground":"text","on":["tone-0",["tone-0","veil"]],"minimum":4.5,"why":"t"}]` gives 2 pairs, and the second pair's `background` deep-equals `['tone-0', 'veil']`.
- `refuses malformed pairs`: these throw `/entry 1:/`: `minimum` missing, `minimum: 30`, `on: []`, `on: "tone-0"`, `why` missing.
- `checks pairs`: with `tokens = parseTokens(SOURCE)`, check the pairs text on tone-2 (minimum 4.5), text on tone-2 (minimum 13), text on nope (4.5) and text on veil (4.5). The statuses are `['pass', 'fail', 'missing', 'missing']`. The third error matches `/Unknown token: nope/` and the fourth matches `/not opaque/`. `checkPairs(tokens, [{ foreground: 'text', background: ['tone-2'], minimum: 12.2, why: '' }])[0].close` is `true` (12.38 against 12.2).
- `describes a pair`: `describePair({ foreground: 'text-dim', background: ['tone-2', 'tone-3'] })` is `'text-dim on tone-2 + tone-3'`.

### Task 3: The `tokens` command-line tool

**Files:**
- Create: `tools/src/bin/tokens.mjs` (port of front-burner `src/bin/tokens.mjs`)
- Test: `tools/src/bin/tokens.spec.mjs`

**Interfaces:**
- Consumes: Task 1's library, `main`, `print`, `table` and `UsageError` from `cli.mjs`, and `describeColour` and `CLOSE_MARGIN` from `colour.mjs`.
- Produces these commands:
  - `list [filter] [--json]`: rows `{ name, value }`. `value` is `var(--x)` for a reference and the hex for a colour.
  - `resolve <token...> [--set token=value] [--json]`: rows `{ token, chain, alpha, ...describeColour }`.
  - `pairs [filter] [--failing] [--close] [--set token=value] [--json]`: JSON `{ total, failing, close, pairs: [{ ...result, pair: string, minimum }] }`. The text table is `pair | min | ratio | status`, followed by `<n> pairs, <f> failing, <c> close.` It exits 1 when any pair is `fail` or `missing`.
  - `try <token=value...> [--json]`: JSON `{ changed: [{ before, after }], failing }`. The text table is `pair | min | before | after | status`, or `No pair changes.` when nothing changed. It exits 1 when any pair fails after the change.
  - An override that does not have the form `token=value` is a `UsageError` (exit 2). A value that is not a colour exits 1.
