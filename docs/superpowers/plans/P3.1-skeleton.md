# P3.1 Skeleton Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Commit a copy of the Breeze style as Amber's Union style, with the identifier `amber`, and show by pixels that Dolphin draws with it, and not with Breeze, without changing a system setting.

**Architecture:** The Breeze style of `plasma-union` 6.8.2 is copied unchanged from `/usr/share/union/styles/breeze/` into `parts/union-style/amber/`. Union takes a style's identifier from its folder name, so the folder is called `amber`. Only `metadata.json` is rewritten, and a licence file is added. A spec in `tools/` checks the folder's structure: metadata, `@import`s and `url()`s. The style is tried in P2.3's nested KWin, which keeps its own configuration, cache, data and state in `tmp/check-colour-scheme/`. Dolphin runs there with `UNION_STYLE_NAME=amber`. Because the copy draws exactly like Breeze, a throwaway marker copy (buttons in magenta) is used once to prove that `amber` is the style being read. Then the clean copy goes back.

**Tech Stack:** `plasma-union` 6.8.2 (`union-styletool`, `union-ruleinspector`), Union CSS, Node 24 with `node:test` for the spec, the `image` tool, the nested `kwin_wayland` 6.8.2 session of P2.3 with Spectacle, Dolphin.

**Spec:** `docs/product/roadmap.md` (row P3.1 and the note under Step 3), `docs/architecture/platform.md` ("Union", "Tools and switches", P0.3's "What it changes", and the nested session under "Colour scheme"), `docs/architecture/overview.md` ("The parts", "Repository layout"), `README.md` ("Licence"), `docs/architecture/decisions.md` (D-24, D-92).

## Global Constraints

- Branch `feat/p3.1-skeleton` from `master`. This plan file is committed on it.
- Use the glossary's words, in British spelling: Union style (or "style"), Breeze style, Union CSS, part, known gap.
- **Never change the owner's system settings.** `widgetStyle=Union` in `~/.config/kdeglobals` is not touched, and nothing under `~/.config` is created or edited. `sha256sum ~/.config/kdeglobals ~/.config/kwinrc ~/.config/dolphinrc` gives the same result at the start (Task 2) and the end (Task 3).
- **Write nothing under `~/.local/share`, if the platform allows it** (my call). The style is found through the nested session's data folders (Task 2, Step 2). Only if neither data folder works may the style be installed with `union-styletool install` to `~/.local/share/union/styles/amber/`, as P0.3 did. In that case it stays installed, and the platform document records it for P6.1 to remove.
- Write nothing under `/usr`.
- **The copy is the Breeze style of `plasma-union-6.8.2-1.fc45` unchanged**, except for `metadata.json` and the added `LICENSE`. No rule is edited in this plan, so P3.2 starts from a known base. Its rounded corners and borders are Breeze's, and P3.2 removes them. This plan draws nothing of Amber's own, so the anti-goals are not checked here.
- **Keep every SPDX header.** BSD-2-Clause asks that the notices travel with the files (README, "Licence").
- `metadata.json` (my call, following Breeze's keys): `"input-type": "css"`, `"input-version": 1`, `"name": "Amber"`, `"description": "Amber's Union style: dark, warm and flat."`, `"version": "0.1"`, `"license": "BSD-2-Clause"`, `"url"` the repository's URL from `git remote get-url origin` (written as https), `"authors"` Breeze's two authors followed by the owner's name as `git config user.name` gives it. No `"hidden"` key.
- Files of the nested session stay in `tmp/` and are not committed.

## Review Focus

- **The application draws with Breeze while the check reports success.** The copy matches Breeze pixel for pixel, so a run that silently falls back to Breeze looks exactly like a run that worked. This happens when the identifier is wrong, the style is not found, or the variable does not reach the process. The test for this is the marker run in Task 2, Step 4: magenta buttons show up with the marker copy and disappear without `UNION_STYLE_NAME`.
- **Dolphin is a single-instance application.** If it is started where another Dolphin already runs on the same D-Bus, it opens a window in the old process, which does not have the variable. The nested session's own `dbus-run-session` prevents this. The marker run would expose it if it did not.
- **A stale style cache.** Union caches each style in `$XDG_CACHE_HOME/union/` by a hash. After the marker copy is replaced by the clean one, the old magenta could still show from the cache. This is pinned in Task 2, Step 5: the clean run's button must measure as Breeze's button colour, not magenta.
- **A relative path breaks in the copy.** `check.css` loads `../images/*.svg`, and a missing image aborts a Qt Widgets application (P0.5: an unmasked or missing background image aborts in `drawBackgroundRectangle`). The spec in Task 1 checks that every `url()` and `@import` resolves, and in Task 2, Step 5 P2.3's probe draws a checked check box with the copy.
- **Union rejects a file it does not expect** (`LICENSE`), or `"input-version"` is required. Pinned in Task 2, Step 3: `union-styletool inspect amber` or the rule inspector must list the style with name "Amber".
